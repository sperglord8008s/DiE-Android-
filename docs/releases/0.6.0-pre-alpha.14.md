# GlassDigestor 0.6.0-pre-alpha.14

Larger recovered PDFs remain usable when PhotoRec establishes their native
footer but its optional newline/date reader reaches a work limit. The exact
native file extent is retained with an explicit partial-metadata status.
Source IO/deadline errors and missing footers remain unresolved. Version code
**20**; input/read/work limits and older capture policies remain unchanged.

A PDF larger than 9 MiB now passes actual gallery/save/preview-handoff and exact
payload export checks. Independent Python verifies every byte and xref/object
location. Native stream/error-class and forged scope/flag/count/legacy checks
pass. All **181 host tests**, required generic/native checks, existing 80/256 MiB
and archive/media regressions, ARM64 PhotoRec compilation/app assembly/lint/APK
verification and corresponding-source packaging pass. The Android lab compiles
and statically verifies its extended large-PDF case; current source CI and
actual API 26/35 execution remain pending before publication.

The publisher also preserves the release display title when iterating uploaded
asset names. Its seven contract tests pass, including resumed-draft publication.
Tags, source identities, asset checksums and immutable APK rules remain guarded.

This is native footer recovery and exact file export. Complete PDF structural
validity, renderer/production ARM64/SAF/handset acceptance and other full
file-check modules remain separate incomplete work. See
[PDF recovery contracts](../pdf-file-recovery.md).
