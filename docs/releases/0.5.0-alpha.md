# 0.5.0-alpha checkpoint

This save point uses application ID `org.diemobile`, version code **5**, Android
API **26–35** and the **ARM64** ABI. The source tag is `v0.5.0-alpha`; development
continues on `codex/workbench-parity`. The existing debug signing configuration
is retained. This is a development alpha, not a claim of complete desktop parity
or handset validation.

## Included functionality

- The primary CDiE desktop scanner, captured settings/rule provenance, compatible
  interpretation selection, named option profiles, persistent document batches,
  exact byte/native-tree comparisons and complete JSON/XML/CSV/TSV captures.
- Typed PE/ELF/thin/fat Mach-O structures, maps/imports/exports/symbols/resources,
  instruction pages, complete native entropy/histograms and all eight whole-file
  digests, with explicit coordinate domains and stored-byte exports.
- Actual Binwalk, PhotoRec and libmpv integrations; classified whole-input/DEX
  strings; EXIF/IPTC/ICC/XMP/media metadata; source-built Google compiled Android
  resources, smali/dexlib2, apksig signing/rotation and package/split relationships.
- Offline pinned engines/knowledge, source/license notices and complete local
  reports. The APK has no INTERNET permission or telemetry.

Detailed implemented-versus-verified scope is maintained in
[FEATURE-PARITY.md](../FEATURE-PARITY.md), with the build continuation in
[continuation.md](../continuation.md).

## Verification and limits

The checkpoint is built from a clean committed source tree. Its APK is verified
for version/application identity, signing, packaged provenance/notices, offline
permissions and static 16 KiB ZIP/ELF alignment of all fourteen native libraries.
The existing automated suite contains **118 API 28 Android host checks**, plus
real host JNI/parser, independent byte/media/Unicode/crypto and AAPT2 references.
Host simulation and cross-compilation do not establish actual Android runtime
behavior.

Real handset/SAF/isolated-UID/Binder/crash/cancellation and 16 KiB runtime checks
remain pending. PhotoRec and Binwalk currently accept whole blobs up to 64 MiB;
other engine-specific limits and unsupported validation/recovery mechanisms are
explicit in their contracts. Desktop heuristics, additional archive families,
fragmented recovery, full framework/split resolution, privileged diagnostics,
complete format parity and reproducible release signing remain incomplete.

The versioned APK/checksum/build manifest, `checkpoint.json`, complete
`SHA256SUMS` and a standalone checkpoint README are retained together as the
save point. CI uploads them as `die-android-alpha-savepoint`. The
manifest records the exact source revision, application version, engine/data
pins and signer certificate. Preserve its original bytes when sharing an APK.
Local and CI debug signing certificates can differ; use the same signer when
updating an existing installation. No signing identity migration is introduced.

## Rebuilding

Check out `v0.5.0-alpha`, then follow the pinned JDK/SDK/NDK and dependency-cache
setup in [README.md](../../README.md) and [continuation.md](../continuation.md).
After preparing dependencies:

```sh
./gradlew --no-daemon :app:assembleDebug :app:lintDebug
bash scripts/verify-apk.sh app/build/outputs/apk/debug/app-debug.apk
```

`verify-apk.sh` checks the packaged version against `app/build.gradle` and writes
`app-debug.apk.sha256` and `build-manifest.txt` beside the APK. The host/UI suite
uses `scripts/test-workbench-ui.sh`. Retained caches permit offline rebuilding;
bit-identical signed APKs across different debug keys/build paths are not
claimed. MPV and PhotoRec source bundles remain part of the CI artifacts and
have separate pinned offline rebuild instructions.

From a clean committed checkout after verification, freeze a checkpoint with:

```sh
python3 scripts/package-alpha.py --output-dir /path/to/new/checkpoint-directory
cd /path/to/new/checkpoint-directory
sha256sum -c SHA256SUMS
```

Packaging verifies source/manifest/APK identity, copies the original manifest
unchanged, checks the copied bytes and publishes a new directory atomically.
Existing checkpoint directories are never replaced. Rebuilding with a different
signer does not alter a previously retained save point.
