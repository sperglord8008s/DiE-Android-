# GlassDigestor 0.6.0-pre-alpha.13

Embedded PDFs can now become actual gallery files with `.pdf` / `application/pdf`
saves. PhotoRec's original PDF file-check runs through a bounded read-only
source-relative stream. Successful native footer results supply the stored
extent; incomplete or read/work-limited checks remain unresolved. Version code
**19**. The combined PhotoRec/Binwalk gallery and real-payload ZIP exports from
pre-alpha.12 remain available.

All **181 host tests** pass with zero failures/errors/skips. Actual native PDF
recovery, gallery handoff/save, exact Java/Python byte/xref checks, scope forgery
refusals and native stream read/seek/write-denial/budget/exception/descriptor
checks pass. Existing media/80 MiB/256 MiB recovery regressions, required generic/
native checks, ARM64 assembly/lint and APK packaging/signature/offline/notices/
alignment verification pass. Matching PhotoRec policy/contract hashes and
corresponding-source notices/bundle are updated.

An eighth Android laboratory case now exercises actual isolated PhotoRec/Bionic
PDF recovery and missing-footer refusal. Both test-only APKs compile and pass
static source/architecture/library/notices/identity checks. API 26/35 execution
and current five-job source CI remain pending before publication.

PDF footer checks do not establish complete structural validity or rendering.
Larger PDFs can hit the optional date-reader work limit. Actual PDF rendering,
production ARM64/SAF/handset acceptance and other full file-check formats remain
incomplete or unverified. See [PDF recovery contracts](../pdf-file-recovery.md).
