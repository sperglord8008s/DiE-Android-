# GlassDigestor 0.6.0-pre-alpha.4

This checkpoint links embedded findings to the native archive workbench.
Android version code **10**; application ID and debug signing configuration
remain unchanged.

- Binwalk and PhotoRec findings can open an explicit source-bound parsing tail
  in the archive browser, including candidates with unknown extents. Original
  reported ranges remain unchanged and no EOF-based recovered extent is inferred.
- Complete original row/provenance and source identity accompany the request,
  survive manual interval changes/restoration and appear in archive exports.
- Caller source SHA-256/size is checked before native parsing. Selected-member
  root identity is carried through native/classic ZIP results, allowing checked
  independent previews after the investigation parent's cache expires.
- Request metadata is bounded during serialization and preserves exact UTF-16;
  invalid identities, numeric types, bounds and oversized contexts are refused.

Standalone actual Binwalk/PhotoRec/libarchive chains decode an independently
generated embedded TAR and a real unknown-extent gzip candidate into the
expected exact member bytes. The complete **151-case Android host suite** passes
with zero failures/errors/skips, plus required generic/native scanner checks,
25/37 archive model regressions, ARM64 assembly/lint and fifteen-library APK
static checks. Source CI/publication are the next gates for this development
slice. See [launch contracts](../archive-launches.md).

Actual Android UID/Binder/SAF/cancel/crash/media/PDF/cache-pressure and 16 KiB
runtime acceptance remain unverified. Passwords, arbitrary deobfuscation,
universal subtype support, persistent per-preview native-origin history and
full desktop DiE parity remain incomplete. Debug-signed ARM64/API 26+ testing
build: compare signer digests before updates and retain the preceding checkpoint.
Offline application; no INTERNET permission, telemetry or inspected-app execution.
