# DEX investigation contracts

Google smali/dexlib2 and baksmali **3.0.10**, source tag commit `7a325fc45dc02d0e428da5b54685e5887903efca`, supply DEX readers and actual smali formatting. Dependencies are version-pinned in Gradle; standalone host tests additionally verify every runtime JAR against `scripts/dex-dependencies.sha256`. Source JAR checksums are in `scripts/dex-sources.sha256`. The complete upstream licensing document and transitive source-header notices are bundled in `assets/notices`. Guava uses the Android variant, 31.1-android. No inspected class is loaded, installed or executed.

The main file/APK report now uses this engine for Unicode/MUTF-8 defined-class names, table counts, per-entry Adler32/SHA-1 consistency and extracted-DEX SHA-256. Conventional APK DEX members require unique names, declared/actual size and CRC32 agreement before class evidence contributes. Metadata enumeration keeps its existing 10,000-entry/1,000-preview bounds; a separate 100,000-record uniqueness pass and 128-name limit prevent ambiguous or unbounded DEX selection. Declared expanded bytes are reserved against the 96 MiB aggregate budget even when a candidate fails. Errors, duplicate names and skipped scopes are disclosed. The separate Exodus adapter now searches original slash descriptors with a bounded Python-compatible regex subset and a required-literal index; unsupported rules/names and incomplete searches stay explicit. See [tracker contracts](tracker-investigation.md); richer input does not imply full Python/acquisition equivalence.

Open **APK / SDKs → DEX tables / bytecode / references / smali** for the typed viewer. ZIP/APK inputs first list names ending in `.dex`, including nonstandard directories; filenames identify candidates, not validated code. Selecting one uses `ArchiveStore`'s complete bounded inventory and directory/size/CRC checks, then a fresh DEX SHA-256. Raw DEX inputs also get an owned private byte snapshot; physical actions use those bytes. Ambiguous names cannot be selected. Inventory limits (20,000 entries/1 GiB ZIP) differ from the summary module's limits above. No automatic recursive discovery or ART execution is implied.

## Evidence model

- `DexDocument` owns an immutable input byte snapshot and freshly computes whole-input SHA-256. `read` acquires a file with length/cancellation checks, `parse` clones caller bytes, and `takeOwnership` explicitly transfers a fresh private buffer without a second blob copy.
- Header allocation/range checks run before constructing upstream readers. MUTF-8 length claims are bounded before decoding, and actual encoded text/terminators are validated with the upstream reader. UTF-16 code-unit counts are distinct from Unicode code points and encoded byte lengths. Embedded NULs and isolated surrogates are preserved; structured UTF-8 exports escape isolated UTF-16 surrogates.
- DEX 035/037/038/039/040 headers use their classic address domain. DEX 041 entries use absolute container offsets. A later header can reference earlier shared data; adding the header offset to those addresses would be wrong. Each entry retains header offset, declared entry/container sizes and the engine's first/last-entry flags. Appended source bytes are disclosed separately.
- Header Adler32 and SHA-1 compare the stated entry's `file_size` span. They are consistency checks, not publisher signatures or a complete ART verifier. A mismatch stays visible while otherwise parseable forensic data can still be inspected. Whole-input SHA-256 also identifies shared container data and overlays outside that entry's checksum span.
- Class definitions, method/field IDs, strings, types, prototypes, handles, call sites and map/header records retain native table indices and source order. Class-data direct/virtual and static/instance groups remain explicit. Duplicate declarations are enumerated with the upstream `skipDuplicates=false` APIs. Method/field ID offsets locate identifier records, not encoded declarations or bodies. Owner mismatches and missing versus explicitly encoded initializers remain distinguishable.
- Values preserve type tags, exact long decimal strings, floating values/IEEE bits, annotations, visibility, parameter names/signatures, hidden-API metadata and raw access flags/unknown bits. Nested values have explicit budgets. Prototypes expose shorty/return/parameter indices; modern references retain handle/bootstrap/extra-argument evidence.

## Bytecode and relationships

`DexCode` delegates instruction decoding to upstream dexlib2. Method-relative addresses count **16-bit code units**. Physical offsets identify bytes in the input DEX/container. Every instruction/payload retains code-unit span, physical range, opcode/format, registers/ranges, literals, reference kinds/indices, branch targets and opcode flags. Raw reference-index operand positions follow the pinned upstream instruction implementations; there is no independent opcode decoder.

Unknown opcodes remain unknown. The engine's NOP fallback is identified explicitly; it does not justify assigning NOP behavior flags to an unrecognized opcode. Instruction bytes have a disclosed 64-byte preview; ordinary instructions fit completely, while full payload ranges remain available. Array previews show at most 64 values; a separate lazy array table exposes every element. Switch case offsets are relative to referring switch instructions, with all origins retained separately. Shared payloads and ambiguous origins do not silently select one base.

Debug and exception tables preserve line/source/local events, associated code addresses, protected half-open intervals, typed handlers and catch-all nulls. Associated code offsets are labeled separately from the bytes encoding those metadata records. Register, incoming-parameter and outgoing-argument word counts describe a frame; they do not prove runtime values.

Reference scans inspect explicit encoded references in all decoded method bodies of the selected entry, including second references in 45cc/4rcc instructions. They retain caller definition/instruction indices and physical offsets. They do not resolve reflection, dynamic dispatch, other DEX entries/splits or runtime reachability. Unknown opcode coverage is reported. A budget or malformed-body failure does not return a successful partial/empty reference table.

A separate [captured multidex definition index](dex-definitions.md) now links
exact type/method/field identifiers and method-handle members to every observed
declaration across selected APK DEX members and 041 container entries. It owns
checked source snapshots, retains duplicates and partial-source diagnostics,
and opens the correct target table before physical byte actions. This does not
expand encoded-use scans into a linker or infer inheritance/framework/split use.

`DexSmali` uses upstream baksmali for method declarations, labels, directives, parameters, annotations, debug items, payloads and exception regions. It supplies a bounded method-only context, with no bootclasspath/deodex execution. Native/abstract declarations have no invented frame/body. The renderer can normalize labels/shared payload representation; original structured offsets and source bytes remain authoritative. The pinned writer cannot emit SET_SOURCE_FILE debug events and still uses a classic-sized header when asked to write 041: fixtures avoid these writer limitations and explicitly construct the tested 041 shared-table container. These are writer limitations, not claims of handset validation.

## Paging, export and budgets

`EvidenceRows` keeps lazy record sources and only the current page. Filters retain matching indices; they do not create a second full evidence DOM. Default pages contain 50 rows, with 1–50 supported by the model for large records. A page is limited to 8 Mi-characters and a row to 4 Mi-characters. Exceeding a limit fails explicitly; rows are not silently clipped.

`InvestigationBackend` separates provider/query relationships from the shared Android viewer. Root views expose every supported pool for every entry. Class records link to method/field declarations; methods/instructions link to bytecode, debug, exception and smali views. Encoded operands link to pool records and explicit use scans; callers return to their instruction page. Arrays expose all elements, switches their encoded targets/origins, debug events their associated code and exception records their handlers. Byte actions use physical locations and checked extents only. Unfiltered jumps open the target page; they do not imply that a reference resolves to a local implementation.

The viewer supports 50/10/1-row pages, explicit Search over all fields, complete record/table exports, range measurements/extraction and hex cross-links. Edited search text stays separate from displayed results. Back retains 64 query/filter/draft/page locations, including across recreation; expiry is disclosed. Full JSON/smali exports are staged before the document picker and survive recreation independently of the live parser/source. Large detail/text dialogs disclose preview limits. A pending export can finish after the input expires; Reload resumes an available investigation if its load was interrupted by a picker result.

Schema `org.diemobile.evidence-table`, version 1, exports captured provenance, query/metadata, table kind/count, displayed filter/page/page-size and every row, independent of the UI filter/page. A full table is streamed into an immutable private `PreparedExport` before SAF handoff. UTF-8 output has a 256 MiB encoded-byte budget and cancellation checks. Invalid unescaped surrogate output fails rather than silently substituting text. A failed/cancelled stage is discarded.

Input: 32 MiB; container: 16 entries; class index: 120,000 records; string pool: one million IDs, one Mi UTF-16 units/string and 16 Mi units/entry; combined string/class container indices: two million. Declaration groups retain up to 200,000 entries including duplicates. Per method: two million code units, 200,000 decoded instructions/payloads, 200,000 debug events, 65,536 try regions and 100,000 handlers. Reference scans cap 200,000 methods, two million instructions and 50,000 matches. Values cap 32 levels/10,000 nodes per record and formatted references one Mi-character.

These are operation/model budgets. Parsers and formatters still run in the app process. Some upstream work must return before cancellation settles; a recursion error is reported where recoverable. Process isolation, hard CPU/memory limits, compact DEX/ODEX/OAT support, complete ART validation, cross-split resolution, Java decompilation and actual handset/API 26/35/16 KiB runtime verification remain pending.

## Reproduce verification

`scripts/test-dex.sh` uses JDK 17 and checksum-pinned host dependencies; `JSON_JAR` and `DEX_DEPS_DIR` support cached offline runs. Fixtures check real serialized class/field/method metadata, Unicode/MUTF-8/NUL/surrogates, exact offsets and integrity, signed-zero/long/annotation values, branches/arrays/switches, debug/exception data, dual/dynamic references, callers, complete filtered-scope exports, smali, streaming cancellation/cleanup, malformed data and decode caps. Synthetic 041 single/shared-entry containers check absolute shared-data addresses and entry-specific integrity. They are not installed or ART-executed.

`scripts/test-workbench-ui.sh` additionally runs four API 28 Robolectric report-integration cases and seven DEX viewer cases, alongside the fourteen native/archive and six string UI cases. Viewer checks exercise 126 real class definitions, explicit Unicode search/drafts, Back/recreation, array/switch/debug/caller links, actual upstream smali, filtered complete exports and captured page size across source mutation/recreation, APK member/root restoration, queued cancellation/reload, classified-string-to-caller links and result space at 360×640. Host provider checks independently cover raw/member ownership, parent versus child provenance, archive indices, exact MUTF-8 classification spans and strict text staging. See [string classification](string-investigation.md). This verifies Android integration with real engine data, not device behavior. CI runs host DEX checks plus ARM64 compilation/lint/package verification.
