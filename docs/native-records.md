# Native record snapshots

`Engine.records` uses the existing pinned CDiE `cdie_memory_map`, `cdie_imports`, `cdie_exports`, `cdie_symbols`, `cdie_resources` and `cdie_disasm` readers. The adapter does not introduce independent executable-format parsers. Calls remain serialized with the scanner and other native tools.

The JSON schema is `org.diemobile.native-records`, version 1. A successful object includes `kind`, `fileType`, `fileSizeBytes`, `scope`, `rowCount`, `metadata` and every returned row. `complete-snapshot` applies to maps/imports/exports/symbols/resources. `instruction-page` describes one native disassembly window; `metadata.nextOffset` explicitly indicates continuation, rather than implying that the entire file was decoded. Unsupported or failed reads return `ok: false` and `error`, distinct from a supported successful empty table.

Each row has a stable zero-based `index`, `name`, nullable numeric `physicalOffset`, nullable hexadecimal-string `virtualAddress`, and nullable decimal-string `sizeBytes`. Unsigned integers use exact strings, preserving all 64 bits. `UINT64_MAX` address and unknown export ordinal sentinels become null. Raw symbol `value` is not an address sentinel: `0xFFFFFFFFFFFFFFFF` remains that exact value. A zero symbol size can mean unknown; it does not justify extracting an empty payload or inferring the next symbol's extent.

| Kind | Additional native fields |
|---|---|
| Memory map | Raw `filePartFlags`, `filePartNumber`, `nativeIndex`, `isVirtual`, `isInvisible`; bounded `nameBytesHex` preserves the provider's name bytes even if JSON substitutes invalid UTF-8. Metadata includes mapping mode, available-mode mask, architecture, bitness, endianness, module/entry VAs and name/record bounds. |
| Imports | `library`, exact `ordinal`, `hint`, `byOrdinal`, `isDelay`. The physical/VA location identifies the IAT slot for PE; it does not identify the import-by-name structure or prove a call. |
| Exports | Nullable exact `ordinal`, `forwarder`. A forwarder redirects to another library/entry; PE aliases follow the provider's first-name-per-slot behavior. |
| Symbols | Raw `value`, source-table `recordOffset`/`tableIndex`, native `kind`/`binding`, `sectionNumber`, `nativeType`, `storageClass`, `auxiliaryCount`, `fileName`, `isUndefined`, `isAbsolute`, `isDebug`. Target offset and symbol-record offset are distinct. |
| Resources | `typeId`, `typeName`, `nameId`, `languageId`, `languageName`, `codePage`. Named identifiers use the native `UINT32_MAX` ID marker. Payload ranges identify stored file bytes; compressed resources are not thereby decoded. |
| Disassembly | `bytes`, `instruction`, `comment`, `decodeAddress`, `addressDomain`. Native CDiE uses file offsets as decode addresses when unmapped, so this adapter cross-checks its mapping using the same native map lookup before presenting a VA. Mapping failure is disclosed, and ambiguous address-domain evidence is marked unknown. |

The detached native providers fail without partial output at their record/text limits: 1,024 map records; 10,000 import/export/symbol/resource records; their published name/text limits. The adapter additionally caps JSON at 16 MiB and returns an explicit error on overflow/allocation failure. Memory-map names are limited upstream to 127 bytes; raw hex represents that bounded provider name, not an unlimited original string. These are output/model budgets, not process isolation or a proof against hostile parser defects.

The Java model validates schema, record counts, row ordering and exact numeric encodings. Paging/search operates on one snapshot without rerunning native parsers. Address lookup retains all covering records, including overlaps and virtual-only intervals; it does not silently select one mapping. Physical range operations validate length and bounds, cap work at 256 MiB, stream data and detect length changes. They do not synthesize virtual bytes, extend a resource beyond its declared range or infer symbol sizes.

Host fixtures exercise the production JNI and Java model together: rich PE32/PE64 named/ordinal imports, exports and forwarders, a known resource payload, COFF auxiliary and UTF-8 names, ELF absolute unsigned values, high Mach-O VAs, exact 10,000-record tables and over-limit failure, and continuity/domain labeling of instruction pages. Model fixtures cover overlapping/virtual mappings, search/paging, numeric overflow, stale ranges, cancellation, read-only extraction and independent known digest/entropy values. Android UI/device behavior is tracked separately in FEATURE-PARITY.md.

## Android workbench

Native Tools opens the memory map by default. Maps, imports, exports, symbols, resources and instructions use searchable 50-row views of the complete detached snapshot. Parameters/help/navigation/export actions occupy a scrollable area; analysis/cancel/paging controls, record search and results remain outside it so the form does not crowd out evidence on a phone. A row opens every original field with contextual definitions, then actions for physical hex/disassembly, symbol-table source bytes, preferred-VA mapping, range analysis and exact stored-byte export where valid. Metadata discloses the actual native mode and snapshot scope. A failed read remains an error; it is not rendered as an empty successful table.

Parameter edits remain drafts until **Analyze / reload**. Results, exports, Back navigation and activity recreation use the captured request that produced the evidence, even when draft controls differ. Navigation history retains 64 parameter/filter/page locations and discloses expiry of the oldest location. It reloads a destination rather than retaining many large models. The current location and a pending prepared export survive recreation; the full Back history does not yet survive recreation/process death.

**Previous/Next 50** moves within a returned table. For disassembly, **Next block** requests the native continuation offset and preserves the selected mode/syntax; it is distinct from a row page. Hex uses physical 4 KiB pages. **Go to offset / VA** accepts unsigned 64-bit preferred VAs, uses the displayed map mode when viewing a map (otherwise the default native map), and exposes every covering record if mappings overlap. A virtual-only mapping cannot open file bytes. These are preferred loader addresses, not evidence of a runtime ASLR base.

Selected ranges are half-open physical intervals. Range analysis streams SHA-256, CRC32 and Shannon entropy from those bytes. Export stages the exact selected bytes privately **before** opening the system document picker. A delayed picker, changed UI or activity recreation therefore cannot change which bytes/report the pending operation writes. Report export includes every returned table row regardless of the UI filter/page; a disassembly report still covers only its returned instruction window. See [report schemas](report-schema.md).

Reports can retain the parent inspection's SHA-256, labeled as such; tool operations do not rehash the whole input. The app passes private input snapshots and reads them only. Length checks detect changed/truncated ranges but cannot establish that a same-length externally modified file still matches an earlier parent identity. A range report always includes its newly measured range digest. Staging is bounded and discarded on normal cancellation/failure/completion. Cleanup of abandoned staging after abrupt process death remains pending.

Table cancellation is checked after acquiring the serialized engine lock and after the native call. A queued cancelled request does not enter native parsing; an active table read must return before its result is discarded. Range I/O checks cancellation between 64 KiB chunks. These checks do not provide native parser isolation, an active table interrupt or a hard CPU/time budget. Some legacy native tools also have to return before cancellation settles.

`scripts/test-workbench-ui.sh` runs nine API 28 native-workbench Robolectric cases using the real Linux JNI and production Activity, not mocked native results. It checks table paging/search/back, disassembly pages, unsigned-VA navigation, dirty controls, range/report export, queued cancellation, pending-export recreation and usable map/disassembly result space at 360×640. Five further cases cover archive acquisition/navigation. A test output stream substitutes for the document provider. Handset/ARM64 execution, real SAF grants, API 26/35 behavior, broader small-screen/accessibility review and actual 16 KiB runtime operation remain separate verification work.
