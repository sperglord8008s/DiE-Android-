# Content-first file presentation and expandable explanations

File info begins with the observed file type, then composition scope, name,
size, entropy and exact input identity. The same header inspection recognizes
ordinary image/audio/media and several archive/compression signatures directly
from bytes, regardless of filename. Recognition is a header observation, not
proof of complete validity, homogeneous contents or successful decompression.
A ZIP/archive/container hint directs attention to content inspection; unknown
embedded layout stays explicitly undetermined until deeper evidence exists.

The duplicate Reference tab is folded into File info. Its complete guide remains
available once, divided into named sections. Direct observations remain expanded
by default; optional terminology/mechanism definitions can expand individually.
Old saved Reference locations resolve to File info. Complete original guide text
is retained in captured report exports.

**Collapse explanations** and **Expand explanations** set the shared presentation
default and update visible definitions. Individual overrides persist until a bulk
operation clears them. Changing definition visibility does not alter scan flags,
source identities, reports, observed facts or the independent state of tool
groups. Main fields, native tool guidance/per-field definitions and the common
investigation viewer use the same controller. Failure/partial-coverage status
remains factual visible information outside optional explanations.

Tools are grouped in this order:

1. Bytes, strings, hashes and comparison.
2. Media and collected metadata.
3. Archives, embedded content and carving.
4. Android applications and knowledge.
5. Executable structures and machine code.
6. Rules, profiles, batches and all native controls.

General tools open first; media/container groups follow the observed header.
Executable tools are available behind their own expandable group. Every native
ID 0–10, every existing investigation provider and the archive/laboratory/profile/
batch/expert entry points remain reachable. The toolbar uses the same catalog.
An old tool-menu callback cannot apply to a later source.

`scripts/test-presentation.sh` checks complete action coverage, guide preservation
and filename-independent header observations. Three actual-Main/CDiE API 28 cases
cover type/priority/group layout, old Reference restoration, bulk definitions
without evidence/settings changes, recreation, exact native tool routing and
stale-source refusal. Existing native/media/resource/carving/export cases test
that statuses and workflows remain available. Hardware and accessibility flows
remain device-unverified.

This is the presentation foundation. **Gallerize**, its concatenated-content
acceptance fixture, actual in-app media playback/gallery, configurable byte/
entropy grids and the broader archive engine are separate active work; this
slice does not claim those features are implemented. See
[gallerize-workbench.md](gallerize-workbench.md).

Combined local verification passes all 127 Android host checks with zero failures,
errors or skips, ARM64 assembly/lint, core/native and PhotoRec streaming fixtures.
APK identity/signature/offline/source-reference and static 16 KiB checks pass;
these remain separate from actual Android runtime verification.
