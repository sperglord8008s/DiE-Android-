# Binwalk library adapter

The Android library compiles unmodified Binwalk source at `26713972e3f9f52dc37d4a421c4554b0bd9e82ef` (Cargo version 3.1.1, MIT). `upstream/Cargo.toml` describes its library dependencies without the desktop CLI/terminal/plotting target and browser-download features. `Cargo.lock` pins the complete resolved dependency graph, including delink `b58c93732c3578af08d39d2fc2aeaada5b1c3ee1`. The app adapter is GPL-3.0-only. Source acquisition refuses to overwrite a modified vendor checkout.

Use Rust **1.90.0** and target `aarch64-linux-android`, JDK 17 and Android NDK **28.2.13676358**. `bash scripts/build-binwalk.sh android` produces the ARM64 JNI library; the Gradle `buildBinwalkAndroid` task also rebuilds it when source/manifest/lock inputs change. `bash scripts/build-binwalk.sh host` builds Linux JNI for tests. `DIE_RUST_ROOT` can point to a standalone toolchain; `BINARY_BUILD_DIR` can retain Cargo output. Cargo's normal cache and `CARGO_NET_OFFLINE=true` support offline rebuilds after acquisition. Gradle `--offline` forwards that setting to its native task. The app performs no downloads.

The adapter uses Binwalk's actual configured patterns and parser callbacks. It scans all overlapping magic positions, including short signatures. It deliberately does not call `Binwalk::scan`, whose normal map construction skips nested records, prunes overlaps and estimates unknown sizes to a following signature/EOF. Raw magic locations, accepted/rejected/panicked parser outcomes, exact parser extents, raw confidence and every catalog pattern remain explicit. No extractor dispatch or analyzed program is executed. Some upstream validators perform in-memory decompression. Rust panics become candidate diagnostics; a native crash/abort is handled by the Android isolated-process boundary.

Limits: 64 MiB input, 20,000 raw magic matches and 32 MiB native report. Overflow checks stay enabled in release builds. JNI duplicates the granted read-only descriptor and closes only its duplicate. The path entry point supports Linux fixtures; Android uses descriptors in `BinaryWorkerService`. Test this distinction and the actual service lifecycle on a handset before treating the runtime boundary as verified.

`scripts/check-binary-notices.sh` verifies committed resolved-dependency and Rust standard-library notices. Regeneration uses `cargo metadata --locked --format-version 1 --filter-platform aarch64-linux-android` and `scripts/binary-notices.py`; review changes before committing. The jni-sys-macros 0.4.1 archive omits workspace license files, so exact upstream MIT/Apache files at its recorded VCS commit are retained under `licenses/`. Bundled native-library license files are included with crate notices. The compiler is not shipped; the linked Rust standard-library notice is.
